# فارسی‌یار — بستهٔ بازسازی‌شده

این بسته شامل فایل‌های سایت، منطق کامل `app.js`، دادهٔ ۱۷ درس، کتاب PDF و فایل‌های SQL است.

## فایل‌ها
- `index.html` — رابط کاربری فارسی و راست‌چین
- `style.css` — ظاهر واکنش‌گرا
- `app.js` — منطق ورود معلم، کلاس زنده، مأموریت‌ها، پاسخ‌ها، امتیاز، تخته و گزارش
- `data.js` — درس‌ها و مسیرهای تدریس
- `supabase-config.js` — آدرس و Publishable key پروژه
- `supabase-schema.sql` — ساخت دیتابیس تازه
- `supabase-fix.sql` — بازسازی توابع ساخت کلاس و امتیازدهی (اصلاح‌شده)
- `supabase-mission-hotfix.sql` — اصلاح کم‌خطر خطای `mission` در دیتابیس فعلی
- `supabase-migrate-existing.sql` — مهاجرت کم‌خطر برای جدول‌های قدیمی پروژه
- `book/chaharom-farsi-1404.pdf` — کتاب پیوست

## برای مخزن فعلی GitHub Pages
1. از مخزن فعلی یک نسخه پشتیبان/کپی بگیر.
2. محتویات پوشهٔ `FarsiYar-fixed` را در ریشهٔ شاخهٔ `main` قرار بده؛ ساختار پوشهٔ `book` باید حفظ شود.
3. `supabase-config.js` از قبل آدرس و Publishable key اعلام‌شده برای پروژه را دارد. کلیدهای `service_role` یا `secret` را هرگز در مرورگر قرار نده.
4. چون دیتابیس فعلی قدیمی است، **فعلاً `supabase-schema.sql` را دوباره اجرا نکن**. از SQL Editor یک نسخه پشتیبان بگیر و فقط `supabase-migrate-existing.sql` را اجرا کن. این فایل ردیف‌ها را حذف نمی‌کند؛ اگر داده‌های تکراری در امتیازها باشد، با پیام روشن متوقف می‌شود و چیزی را پاک نمی‌کند.
5. پس از انتشار GitHub Pages، صفحه را در یک برگه ناشناس باز کن تا فایل‌های قبلی از حافظهٔ مرورگر استفاده نشوند.

## نکتهٔ آزمون
فایل‌های JavaScript با `node --check` بررسی شده‌اند. این محیط امکان اتصال واقعی به Supabase پروژهٔ شما یا اجرای تست مرورگر آنلاین را ندارد؛ بنابراین ورود Auth، RLS و Realtime باید پس از بارگذاری در پروژهٔ واقعی بررسی شوند.

## اصلاح فوری خطای mission
1. در Supabase فقط فایل `supabase-mission-hotfix.sql` را یک بار اجرا کنید.
2. در ریشهٔ مخزن GitHub Pages، فایل `app.js` این بسته را جایگزین نسخهٔ فعلی کنید.
3. در مرورگر یک برگه ناشناس باز کنید یا حافظهٔ سایت را پاک کنید؛ سپس ورود و ساخت کلاس را امتحان کنید.
4. فایل `supabase-config.js` فعلی خود را حفظ کنید؛ لازم نیست کلید اتصال را عوض کنید.

این بسته خطاهای شناخته‌شدهٔ ارسال `mission: null` را اصلاح می‌کند. آزمایش واقعی در پروژهٔ Supabase و GitHub Pages کاربر از این محیط قابل اجرا نیست.


## افزونهٔ فیلم، گفت‌وگوی کلاس و وضعیت زنده
- `supabase-media-chat-migration.sql` یک مهاجرت افزایشی برای کتابخانهٔ فیلم، گفت‌وگوی کلاس و وضعیت شروع/پایان کلاس است؛ جدول‌ها و داده‌های اصلی را حذف نمی‌کند.
- پیش از اجرا، از دیتابیس فعلی نسخه پشتیبان بگیرید. سپس این فایل را یک بار در Supabase SQL Editor اجرا کنید.
- فایل‌های ویدیو در bucket عمومی `farsiyar-videos` ذخیره می‌شوند تا مرورگر دانش‌آموز بتواند آن‌ها را پخش کند. **هر فردی که URL یک ویدیو را داشته باشد می‌تواند آن را مشاهده کند**؛ ویدیوهای شخصی یا دارای اطلاعات خصوصی بارگذاری نکنید. سقف هر فایل ۱۰۰ مگابایت است.
- ارسال پیام دانش‌آموز از طریق RPC انجام می‌شود و نام او باید در فهرست همان کلاس باشد. گفت‌وگو در مرورگر هر چند ثانیه تازه‌سازی می‌شود.
- وضعیت «شروع/پایان کلاس» به‌صورت زنده نمایش داده می‌شود؛ این قابلیت به‌تنهایی تماس صوتی/تصویری نیست.
- تماس صوتی/تصویری چنددانش‌آموزی در این نسخه فعال نشده است. برای پیاده‌سازی پایدار آن به سرویس WebRTC/شبکهٔ سیگنالینگ و معمولاً TURN نیاز است؛ افزودن دکمهٔ ظاهری بدون این زیرساخت تماس واقعی ایجاد نمی‌کند.

## انتشار نسخهٔ افزوده‌شده
1. ابتدا از مخزن GitHub یک نسخه پشتیبان بگیرید.
2. محتویات این ZIP را در شاخهٔ `main` قرار دهید و ساختار `book/` را حفظ کنید؛ تنظیمات `supabase-config.js` پروژهٔ خودتان را حفظ کنید.
3. در Supabase از دیتابیس نسخه پشتیبان بگیرید و فقط `supabase-media-chat-migration.sql` را برای قابلیت‌های جدید اجرا کنید. اگر دیتابیس فعلی قدیمی است، راهنمای مهاجرت قبلی همین README را نیز رعایت کنید؛ `supabase-schema.sql` را روی دیتابیس موجود اجرا نکنید.
4. پس از انتشار، ابتدا ورود معلم، ساخت/بازشدن کلاس، ذخیره فهرست، ارسال مأموریت، و سپس آپلود یک ویدیوی آزمایشی کوچک و چت را آزمایش کنید.
5. اگر بارگذاری فیلم با خطای مجوز مواجه شد، سیاست‌های Storage و اینکه کاربر معلم مالک همان کلاس است را بررسی کنید؛ هرگز برای رفع خطا کلید `service_role` را در سایت قرار ندهید.
